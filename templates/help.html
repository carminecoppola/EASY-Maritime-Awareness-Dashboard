First startup

Recommended workflow

This dashboard monitors RGB and thermal feeds, saves useful captures and organises data for inference and fine-tuning.

1 · Live Check that all three previews are updating and no feed remains in an error state.
2 · Mission Start a mission before saving data so the system can create a session manifest.
3 · Capture Save sensor captures and use the Analysis page to produce samples and AI results.
4 · Archive Review saved photos and the activity log to confirm what was stored and identify any errors.
Live

When is a feed really live?

The Live page updates feed status and FPS automatically. An offline feed does not mean the server has stopped; it means that camera is not delivering recent frames.

Mission

Why start a mission?

A mission groups collected data. Captures, inference runs and detections are indexed in its manifest while the session is active, or when analysis opens one automatically.

Detections

What should I expect from AI?

Start analysis runs inference on the selected source. Results appear as current detections, events and manifest entries. If no new detections appear, check the frame source and activity log.

Photos and activity

Where are images stored?

Photos are stored locally on the Raspberry Pi and shown in the archive. The activity log helps distinguish hardware errors from normal waiting states.

Quick checklist

Before collecting important data

These checks reduce incomplete datasets and sessions that are difficult to interpret later.

  • Left and right RGB feeds have recent frames.
  • The thermal sensor is producing real frames or is clearly marked unavailable.
  • A mission is active before collecting captures intended for fine-tuning.
  • The session dataset reports consistent samples and RGB/thermal pairs.
  • The activity log does not show repeated hardware errors.
